# Design

## Context

- 원 모델 `MVN_DDI.forward((h, t, rels, b_graph))`는 (약물 h, 약물 t, 관계 r) 하나가 참일 점수를 낸다. 관계 분류기가 아니라 삼중항 점수기다. 그래서 쌍 하나의 관계를 알려면 86개 관계를 모두 넣어 점수를 비교해야 한다.
- 입력 그래프는 `data_preprocessing.py`가 만든다. 원자 특징은 SMILES에서 바로 계산하고(`atom_features`, 원소 44종 + `Unknown`), 두 약물의 원자를 모두 잇는 이분 그래프(`get_bipartite_graph`)를 쓴다. 이 모듈은 import할 때 작업 폴더 기준 상대 경로 `drugbank_test/...`로 데이터를 읽는다.
- `forward`는 입력 그래프의 `x`를 그 자리에서 덮어쓴다. 그래서 같은 그래프 객체를 여러 번 재사용하면 안 된다.
- DSN-DDI 약물 1,706개 중 20개는 fold0 train에 나오지 않는다. inductive 모델은 `inductive_data/fold3`으로 학습되었다.
- 약물 이름 사전 `dbvocab.csv`: 13,475행, 칼럼은 `DrugBank ID, Common name, Synonyms`(` | `로 구분) 등. DSN-DDI 약물 중 1,701개를 포함한다.
- 환경 ①은 아직 없다. OpenHands가 기본 이미지 위에 자동으로 설치한다(OpenHands 연결 change에서 확인).

## Goals / Non-Goals

**Goals:**
- 서버는 원 저장소의 그래프 생성 코드를 그대로 재사용해, 원 모델과 같은 점수를 낸다
- `ddi` 패키지는 환경 ①의 파이썬 버전에 의존하지 않는다

**Non-Goals:**
- micro agent 프롬프트, OpenHands 연결
- 정답(채점 기준) 생성 스크립트 (질문 세트 change)
- 모델 재학습, 확률 보정

## Decisions

- **서버는 원 `data_preprocessing`을 import해서 그래프를 만든다.** 서버 프로세스의 작업 폴더를 `/opt/DSN-DDI`로 두고 `drugbank_test`를 `sys.path`에 넣는다. 그러면 원자 특징과 이분 그래프 생성 코드를 다시 짜지 않아도 되고, 원 모델과 점수가 같아진다. 신약 SMILES는 `Chem.MolFromSmiles`로 읽은 뒤 같은 `get_mol_edge_list_and_feat_mtx`를 쓴다.
  - 대안: 그래프 생성 코드를 새로 작성. 원본과 어긋날 위험이 있어 채택하지 않음.
- **쌍 하나씩 계산한다 (배치에 다른 쌍을 섞지 않음).** 원 모델은 이분 그래프에 PyG `GATConv`(기본값 `add_self_loops=True`)를 쓴다. 여러 쌍을 한 배치로 묶으면 self-loop가 배치 전체의 원자 번호 기준으로 붙어서, **다른 쌍의 원자끼리 연결이 생긴다.** 그래서 같은 쌍이라도 함께 묶인 쌍에 따라 확률이 달라진다(같은 쌍 86개를 한 배치로 넣으면 0.28~0.67). 쌍 하나만 넣으면 이런 섞임이 없다.
  - 구현: 그래프 부분은 관계와 무관하고 관계는 마지막 RESCAL에서만 쓰인다. 그래서 쌍 하나(배치 크기 1)에 `rels = [[0..85]]`를 넘겨 한 번의 forward로 86개 점수를 얻는다. 관계를 하나씩 따로 계산한 값과의 차이는 5e-7 이하였다.
  - 확률은 관계마다 `sigmoid(score)`이다. 86개의 합이 1이 되는 분포가 아니므로, 문서와 응답에는 "관계별 확률"이라고 적는다(softmax는 원 모델이 학습한 의미와 달라서 쓰지 않음).
  - 채점 기준(정답 생성)도 같은 방식으로 계산한다. B가 여러 쌍을 묶어 계산해 답이 달라지면 실패로 치되, 실패 원인을 "배치 섞임"으로 따로 집계한다. B에게는 이 규칙을 알려주지 않는다(DSN-DDI 고유의 숨은 규칙이고, 이를 담는 것이 C의 ACI).
  - 원 스크립트는 양성 샘플끼리, 음성 샘플끼리 따로 배치로 묶는다. 그래서 섞임이 같은 정답끼리만 일어나 점수가 올라간다. 테스트셋 3,000건 예비 측정: 쌍 하나씩 계산하면 정확도 0.868, 원 방식 0.964, 양성과 음성을 섞어 묶으면 0.675. 모델 성능은 논문 수치를 인용하고, 이 방식으로 성능을 다시 평가하지 않는다(이 연구의 범위 밖). 위 수치는 계산 방식을 정한 근거로만 남긴다.
  - 검토한 대안: 원 스크립트처럼 배치로 계산. 같은 질문에도 답이 바뀌어 채점 기준을 만들 수 없어 채택하지 않음.
- **결합이 없는 약물(원자 1개, DSN-DDI 약물 중 20개)은 빈 간선을 `(2, 0)` 모양으로 바꿔 넣는다.** 원 코드가 만드는 빈 간선은 1차원이라, 배치 크기 1에서는 PyG `remove_self_loops`가 에러를 낸다. 여러 쌍을 묶은 배치에서는 다른 그래프의 간선과 합쳐져서 드러나지 않았다.
- **모델 선택 기준은 fold0 train 약물 집합이다.** 두 약물이 모두 그 집합에 있으면 transductive, 아니면(또는 SMILES 신약이면) inductive를 쓴다.
- **서버는 파이썬 표준 라이브러리 `http.server`(ThreadingHTTPServer) + JSON으로 만든다.** 환경 ②에 새 패키지를 깔지 않는다. 포트는 `127.0.0.1:8765`로 고정한다. 엔드포인트는 `GET /health`, `POST /predict`(`{"d1", "d2", "top_k"}`, d1/d2는 DrugBank ID 또는 `{"smiles": ...}`)다. 요청은 GPU 하나에서 순서대로 처리한다(lock).
- **`ddi` 패키지는 표준 라이브러리만 쓰고, pandas는 있으면 쓴다.** HTTP는 `urllib`로 보낸다. `predict_many`는 pandas가 있으면 DataFrame을, 없으면 dict 목록을 돌려준다. `save_results`는 `csv` 모듈로 쓴다. 이름 사전과 설명 파일은 패키지 데이터로 함께 넣는다.
- **`resolve_drug`는 정확히 일치할 때만 받는다.** 대표 이름과 동의어를 소문자로 바꿔 비교한다. 부분 일치는 쓰지 않는다(예: "Warfarin"이 다른 약물의 동의어 일부와 겹침). 일치가 여러 개이면 후보와 함께 에러를 낸다. SMILES 판별은 DrugBank ID 형식(`DB\d{5}`)도 아니고 사전에도 없는 문자열을 서버에 보내 RDKit이 읽을 수 있는지로 한다.
- **에러와 경고의 구분:** 계속 진행할 수 없으면 에러(예외), 결과는 내지만 조심해야 하면 결과의 `warnings` 목록에 넣는다. 모르는 약물과 해석할 수 없는 SMILES는 에러, 학습셋 밖·신약·unknown 원자는 경고다.
- **C 전용 이미지 `ddi-specialist`를 따로 만든다.** `docker/Dockerfile.specialist`는 `FROM ddi-runtime`으로 시작해 `server/`, `ddi/` 패키지(사전 포함)를 넣고, 컨테이너가 시작될 때 서버를 띄운다. B는 `ddi-runtime`을 그대로 쓰므로 서버 코드와 패키지가 들어가지 않는다(`runtime-image`, `comparison-conditions` spec).
- **환경 ① 대신 `python:3.11` 컨테이너로 `ddi`를 테스트한다.** 서버 컨테이너와 같은 네트워크(`--network container:<서버>`)로 붙여 localhost 서버를 호출한다.

## Risks / Trade-offs

- [86개 관계 확률이 서로 독립이라 여러 관계가 동시에 높게 나올 수 있음] → 상위 k개를 보여주고, 문서에 "관계별 확률"이라고 명시한다
- [채점 기준을 만들 때 이 서버를 그대로 쓰면, C의 충실도가 저절로 100%가 됨] → 질문 세트 change에서 채점 기준은 원 저장소 코드로 따로 계산하는 독립 스크립트로 만든다. 서버 spec의 "원 모델과 일치" 시나리오로 둘이 같은지만 확인한다
- [원 논문 수치(배치 방식)와 서버의 쌍 하나씩 계산 성능이 다름] → A·B·C 비교는 모델 출력 기준으로 채점하므로 영향이 없다. 성능은 논문 수치를 인용하고, 연구 문서에 "모델·가중치는 원본, 계산은 쌍 하나씩"이라고 적는다
- [OpenHands 환경 ①에서 `ddi` 패키지를 어떻게 자동 import할지 아직 모름] → 이번에는 일반 파이썬 패키지로 만들고, 자동 import 방식은 OpenHands 연결 change에서 정한다
- [사전 원본 저장소 이름이 이미 한 번 바뀌었음] → 빌드할 때 받은 파일의 sha256(`4f19fe91…66d36e2`)을 확인한다
